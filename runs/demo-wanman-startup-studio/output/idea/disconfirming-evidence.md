# Disconfirming Evidence

## Strongest counterargument

The strongest reason not to build Wanman Startup Studio is that founders may not want a separate operating system for validation. They may already use chat threads, notes, advisors, and direct customer calls. The value of a scripted local workflow could be obvious to the builder but invisible to the buyer.

A second counterargument is that founders often say they want discipline, but in the moment they choose speed. If the product blocks MVP work, users may bypass it and ask an AI coding tool to build anyway.

## Kill criteria

Kill or pivot the idea if customer interviews show any of the following:

- Founders do not recognize premature AI-assisted building as a recurring problem.
- Founders cannot recall recent examples where a stronger validation gate would have changed their decision.
- The workflow is seen as consulting methodology rather than software.
- Users want customer access, distribution, or funding help more than stage-gated artifacts.
- The local file workflow is a deal-breaker for the first reachable segment.

## What would change our mind

The case becomes stronger if multiple founders show messy validation artifacts and say they would reuse a structured run before every MVP decision. It becomes much stronger if they ask to run the workflow on a current idea during the interview.

The case weakens if users only praise the concept abstractly but do not offer a real idea, real notes, or a recent painful build decision.

## Bias check

The team is likely biased toward agent orchestration because it already built an AI product research workflow. That existing work is useful, but it can also hide the question of whether founders want a broader startup operating system.

## Current recommendation

Continue to MVP Gate only for a narrow version: Idea Stage plus MVP scope control for technical founders. Do not build Launch or Scale automation until real users complete Idea runs and ask for the next stage.
