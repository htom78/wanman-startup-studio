# Landing Page Experiment

## First viewport

Headline: "Know when your AI-built startup idea is ready for MVP."

Target user: solo technical founders and small AI-native teams.

Promise: turn a raw idea into evidence, counterarguments, competitor context, and an explicit build/no-build gate.

Visible proof: show the artifact list and the fact that the promotion script blocks MVP work unless the Idea Gate says `ALLOW_MVP`.

## CTA

Primary CTA: "Run my current idea through the gate."

Signal measured: whether a founder is willing to bring a real current idea into the workflow. A weak signal is clicking to view the sample. A stronger signal is submitting or sharing a real idea for a guided run.

## Smoke test

Run a concierge test before building a public landing page app:

1. Show the demo run to five technical founders.
2. Ask each founder to bring one current idea.
3. Run the Idea Gate manually with the module artifacts.
4. Measure whether they accept, reject, or challenge the gate decision.
5. Ask what they would pay for: local kit, hosted team workflow, or assisted validation.

This smoke test should produce customer evidence before investing in frontend polish.

## Claims

- Fact: the current repo has scripts for creating runs, validating stages, and promoting to MVP Gate.
- Fact: the demo includes Idea and MVP Gate artifacts.
- Inference: stage gates can reduce premature building for AI-native founders.
- Assumption: founders will value a local workflow over generic chat prompts.
- `needs verification`: willingness to pay, preferred package, competitor pricing, and demand size.

## Do not build

Do not build a hosted dashboard, onboarding flow, analytics stack, payment page, or polished marketing site yet. Do not create testimonials or market-size claims before interviews. Do not convert the landing page experiment into the product itself.
