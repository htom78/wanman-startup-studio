# MVP Gate

## Purpose

Translate validated demand into the smallest build that can create real usage evidence without accumulating uncontrolled technical debt.

## Required Evidence

- MVP scope has clear in-scope and out-of-scope boundaries.
- Architecture brief records durable technical decisions.
- Measurement framework defines activation, retention, revenue, referral, and instrumentation.
- Security review identifies data, auth, abuse, and pre-launch risks.
- First sprint can be executed without expanding the product surface.

## Legal Decisions

- `Decision: BUILD`
- `Decision: REVISE`
- `Decision: STOP`

## Pass Standard

Use `BUILD` only when the MVP has a bounded user workflow, measurable success criteria, and acceptable operational risk for first real users.
